The `domain` parameter (part of the optional `context` object) tells Tolka the clinical setting the text was spoken in. This is not a filter — it actively changes how the translation is produced, by resolving ambiguous terms and adjusting register.

:::note[No default domain]
`context` — and `domain` within it — is optional on `/translate` and `/safe-translate`. If you omit it, Tolka falls back to a generic enrichment with no domain-specific disambiguation, rather than silently assuming any one domain. Pass an explicit domain whenever you know the clinical setting.
:::

---

## Available domains

### `emergency`

**Use for:** Emergency departments, acute care, ambulance communications, triage.

Prioritises **speed and clarity**. Translations favour short, direct, unambiguous phrasing and avoid idioms. Assumes the communication is time-critical.

---

### `gp`

**Use for:** General practice consultations, primary care, routine appointments.

Prioritises **accuracy and nuance**. Preserves ambiguity faithfully where the patient's own description is imprecise, rather than over-interpreting it.

---

### `specialist`

**Use for:** Specialist consultations — cardiology, dermatology, oncology, and similar.

Prioritises **accuracy and nuance** with precise, technical medical terminology. Clinical meaning is preserved exactly rather than simplified.

---

### `mental_health`

**Use for:** Psychiatric consultations, psychological assessments, mental health triage.

Prioritises **sensitivity and accuracy**. Uses non-stigmatising language and preserves emotional nuance — subjective feelings are translated faithfully rather than reduced to clinical jargon.

---

### `physical_therapy`

**Use for:** Physiotherapy sessions, rehabilitation, movement and exercise assessment.

Prioritises **accuracy and nuance** with precise anatomical and movement terminology, and distinguishes between types of pain (sharp, dull, radiating).

---

## Why domain matters: two examples

### Example 1: "trykk" / "pressure"

The same Norwegian word maps to physically distinct concepts depending on domain:

| Domain              | How `trykk` / "pressure" is resolved              |
| -------------------- | -------------------------------------------------- |
| `emergency`          | blood pressure — resolved immediately, no ambiguity preserved |
| `gp`                 | could be blood pressure or psychosocial stress — ambiguity preserved if unclear from context |
| `mental_health`      | emotional/psychological pressure, not blood pressure |
| `physical_therapy`   | physical force or compression applied to the body during exercise or examination |

### Example 2: "vondt" / "pain"

| Domain              | How `vondt` / "pain" is resolved |
| -------------------- | --------------------------------- |
| `emergency`          | acute physical pain |
| `gp`                 | general pain — location and character clarified where possible |
| `mental_health`      | emotional pain / distress |
| `physical_therapy`   | localized physical pain |

:::caution[Wrong domain = wrong translation]
A `mental_health` text sent with `domain: "physical_therapy"` will be translated assuming physical force or physical pain, discarding the emotional meaning entirely. Match the domain to the actual clinical context.
:::

## Choosing a domain

If your integration serves multiple clinical contexts, pass the domain dynamically based on the care setting:

```typescript
function getDomain(careContext: CareContext): ClinicalDomain {
  switch (careContext) {
    case 'ED': return 'emergency';
    case 'GP_VISIT': return 'gp';
    case 'SPECIALIST_CLINIC': return 'specialist';
    case 'PSYCH': return 'mental_health';
    case 'PHYSIO': return 'physical_therapy';
    default: return 'gp';
  }
}
```
