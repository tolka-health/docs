Tolka has two translation endpoints:

| Endpoint | Mode | Behaviour on low confidence |
|----------|------|-----------------------------|
| `POST /v1/medical/translate` | Standard | Always returns a translation, even for `"critical"` risk |
| `POST /v1/medical/safe-translate` | Safe | **Withholds the translation** if risk exceeds the safe threshold |

---

## When to use safe mode

Use `POST /v1/medical/safe-translate` in clinical settings where **displaying an incorrect translation is more dangerous than displaying no translation**. This is the recommended mode for:

- Emergency department triage
- Medication instruction delivery
- Any context where a clinician cannot easily verify the translation

Use standard `/translate` when you need to always receive a translation (e.g., to log it for later review, to display it to clinical staff rather than patients, or to run batch processing pipelines).

---

## How safe mode works

When `risk` is `"high"` or `"critical"`, a safe mode response **withholds** the translation:

```json
{
  "translation": null,
  "back_translation": null,
  "confidence": 0.54,
  "risk": "critical",
  "flags": [{ "type": "negation_flip", "detail": "…", "severity": "critical" }],
  "suggestion": "Please rephrase using simpler language",
  "reason_class": "critical_flag",
  "escalation_options": [
    { "type": "human_interpreter_dispatch", "label": "Request a human interpreter" },
    { "type": "clinician_acknowledgment", "label": "Clinician acknowledges risk and proceeds" }
  ],
  "verified": false,
  "metadata": {
    "latency_ms": 1120,
    "model": "tolka-v1",
    "request_id": "req_01HX...",
    "data_residency": "unknown"
  }
}
```

`translation` and `back_translation` are `null`, and `verified` is `false`. There is no `withheld` field — `translation === null` **is** the signal that the response is intentionally incomplete. `reason_class` and `escalation_options` are present only on this refusal path.

:::note[A refusal is not an error]
A `200` status code is still returned. This is a safety outcome, not a failure. Your UI should treat `translation === null` as "translation not available — use fallback."
:::

## UI pattern for withheld translations

```typescript
const result = await tolka.safeTranslate({
  text, source_language, target_language, mode: 'safe', context: { domain },
});

if (result.translation === null) {
  return showRefusalMessage({
    reason: result.flags,
    reasonClass: result.reason_class,
    escalationOptions: result.escalation_options,
    fallbackInstructions: 'Please use a professional interpreter for this exchange.',
  });
}

// Safe to display
displayTranslation(result.translation);
```

## What to show the clinician when a translation is withheld

1. **Explain** that the translation did not meet quality standards (not that "an error occurred").
2. **Show the flags** if they are meaningful to the clinician (e.g., "A negation may have been lost in translation" — use each flag's `detail` string, or your own copy keyed by `type`).
3. **Offer the real `escalation_options`** the response gives you — a professional interpreter, a telephone interpretation service, or re-phrasing the question in simpler terms per `suggestion`.
4. **Do not retry automatically** without user action — a re-translation of the same text will produce the same result.
