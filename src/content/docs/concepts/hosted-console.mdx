The Hosted Console is a browser-based translation UI at `console.tolka.health/<org-slug>`, for evaluation and pilots. A clinician signs in with a scoped token or a test key, without writing integration code. Larger integrators typically build on the [Web SDK](/sdks/web/installation/) or the API directly instead.

Tolka is in development and does not replace a qualified interpreter.

---

## What it is

- **Org-scoped by URL path.** Each org gets `console.tolka.health/<org-slug>`; there's no separate per-org deployment.
- **Sign in with a scoped token or a test key.** A clinician pastes a short-lived [scoped token](/concepts/scoped-tokens/) (`tka_...`) or an `sk_test_` key. The Console checks the credential against the API before signing in, and shows a message if it is rejected or cannot be checked.
- **A working translation UI**, built on the same `<tolka-translate>` web component covered in [Web Components](/sdks/web/web-components/) — not a separate, bespoke interface.

---

## What the Console does and does not do

- **Public API only.** The Console is built on the same public API surface (`/v1/medical/*`, `/v1/admin/*`) that any integrator uses. A Console feature that needs something the API does not offer has to land on the API first.
- **Static files.** The Console ships as static files served by `nginx`, with no Node.js runtime in the deployed image.
- **Credential in the tab only.** The credential you sign in with is kept in the browser tab's `sessionStorage` so a reload does not sign you out. It is cleared when you sign out or close the tab, and is never put in `localStorage`, a URL or a cookie. A live (`sk_live_`) key is rejected at sign-in because the Console is a shared public origin.
- **No patient text in browser storage.** The Console does not write patient text or translations to browser storage. It remembers only non-patient selections for the tab (language pair, domain, speaker, mode, lookup tab) and your light/dark/system theme choice (the theme is remembered across sessions in `localStorage`). The Console sends no analytics events, and none captures translation content.

---

## Features

- **Translate and Playground.** Where free-text translation is enabled for your environment, translate with clinical context, or open the Playground to inspect confidence, back-translation and risk flags. Free-text translation may be switched off in the hosted environment; pre-written phrases (pending clinical review) are available.
- **Phrase picker** for [templates-only](/concepts/templates-only-mode/) organizations: free text is hidden and phrases are chosen from a list.
- **Audio playback and a voice picker** where [speech](/concepts/speech/) is enabled. Speech is off by default, and the browser's speech engine is the fallback.
- **Light, dark or system theme.**

## Current scope

The Console covers sign-in, a `<tolka-translate>` mount, the Playground and the phrase picker. It does not yet include a dedicated multi-turn conversation UI or an admin dashboard for keys/usage/audit-log — those are tracked as follow-on work, not silently-missing features.
