GP consultations involve multiple back-and-forth exchanges. Using sessions ensures each exchange benefits from consistent clinical context, and avoids passing `domain`/`speaker` on every call.

:::note[Sessions carry context, not language]
A session only inherits `domain` and `speaker`. You must still pass `source_language` and `target_language` on every `translate()`/`safeTranslate()` call — they're never inferred from the session, since the same consultation can involve translating in either direction turn by turn.
:::

---

## Consultation flow with sessions

<Steps>
1. **Create a session when the consultation starts**

   ```typescript
   import { TolkaClient } from '@tolka/web-sdk';

   const tolka = new TolkaClient({ apiKey: process.env.TOLKA_API_KEY! });

   // Called when the GP opens the patient consultation screen
   const session = await tolka.createSession({
     domain: 'gp',
     speaker: 'doctor',
   });

   // Store in component state — not in localStorage. `let` because every
   // subsequent call refreshes it (step 2).
   let sessionToken = session.session_token;
   ```

   Sessions have a fixed 15-minute idle TTL and a 60-minute hard maximum — there's no way to configure a longer window.

2. **Translate each exchange using the session token**

   ```typescript
   // GP types a question; translate to patient's language.
   // source_language/target_language are still required every call.
   const result = await tolka.safeTranslate({
     text: 'Har du hatt feber de siste dagene?',
     source_language: 'no',
     target_language: 'ar',
     mode: 'safe',
     session_token: sessionToken,
     // domain/speaker inherited from the session; omit context entirely
   });

   // Every response made with a session_token includes a refreshed one —
   // store it back, or the idle TTL will lapse early.
   sessionToken = result.session_token ?? sessionToken;
   ```

3. **Handle risk per exchange**

   ```typescript
   import type { TranslateResponse } from '@tolka/web-sdk';

   function handleExchange(result: TranslateResponse) {
     if (result.translation === null) {
       return showRefusal(result.flags, result.reason_class);
     }
     if (result.risk === 'high') {
       return showAcknowledgmentPrompt(result);
     }
     return showTranslation(result.translation, result.risk);
   }
   ```

4. **Close the session when the consultation ends**

   Sessions expire automatically after 15 minutes of inactivity (or 60 minutes regardless of activity). You don't need to explicitly close them, but creating a new session for each consultation is best practice — it prevents context bleeding between patients.

</Steps>

## Example consultation UI pattern

```tsx
function ConsultationTranslation({ initialSessionToken }: { initialSessionToken: string }) {
  const [exchanges, setExchanges] = useState<Exchange[]>([]);
  const [sessionToken, setSessionToken] = useState(initialSessionToken);

  async function onSubmit(text: string, sourceLanguage: string, targetLanguage: string) {
    const result = await tolka.safeTranslate({
      text,
      source_language: sourceLanguage,
      target_language: targetLanguage,
      mode: 'safe',
      session_token: sessionToken,
    });

    if (result.session_token) setSessionToken(result.session_token);

    setExchanges((prev) => [
      ...prev,
      {
        source: text,
        translation: result.translation,
        backTranslation: result.back_translation,
        risk: result.risk,
        flags: result.flags,
        withheld: result.translation === null,
        timestamp: new Date(),
      },
    ]);
  }

  return (
    <div>
      <ExchangeHistory exchanges={exchanges} />
      <TranslationInput onSubmit={onSubmit} />
    </div>
  );
}
```

## Session expiry guidance

There's no per-consultation TTL to configure — every session gets the same fixed 15-minute idle window and 60-minute hard cap. Design around that instead:

- Keep sending the refreshed `session_token` on every call to reset the idle clock — a session that's actively used for a 45-minute consultation stays alive.
- A gap of more than 15 minutes between exchanges (patient steps out, GP gets interrupted) expires the session regardless of the 60-minute cap.
- Expired sessions return `400 session_expired`. Your UI should create a new session silently and continue, not surface the error to the clinician.
