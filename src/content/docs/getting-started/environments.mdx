Tolka serves test and production traffic from the same base URL. The key prefix on each request determines which path it takes through the pipeline.

## Environment summary

| Environment | Base URL | Key prefix | Suitable for |
|-------------|----------|-----------|--------------|
| **Test** | `https://api.tolka.health` | `sk_test_...` | Integration development, CI pipelines. Request via [tolka.health](https://tolka.health). |
| **Production** | `https://api.tolka.health` | `sk_live_...` | Live patient-facing deployments. Issued after a pilot agreement. |

Test and production responses go through the same translation pipeline — only billing, quota, and `key_prefix` audit attribution differ. There is no quality-of-output difference between key types.

## Supported languages

| Language | Code |
|----------|------|
| Norwegian Bokmål | `no` |
| English | `en` |
| Arabic | `ar` |
| Somali | `so` |
| Polish | `pl` |
| Ukrainian | `uk` |

Language codes follow **ISO 639-1**. Pass them in `source_language` and `target_language` — any of the six is valid in either position, as long as the two differ.

Norwegian↔X is the most heavily validated direction for each language (the golden-fixture regression suite runs `en↔no`, `no↔ar`, `no↔pl`, `no↔so`, and `no↔uk`). Cross-pairs that don't route through Norwegian (e.g. `ar↔pl`) go through the same pipeline but have less production validation behind them — treat `risk` and `confidence` as even more load-bearing for those pairs.

:::caution[Low-resource language pairs]
Somali (`so`) has an adjusted, lower confidence baseline in both directions against every other supported language, reflecting more limited LLM training data for that pair. Always rely on `risk` as your primary UI signal rather than the raw `confidence` float.
:::

## Clinical domains

Pass one of these values in the `domain` field:

| Value | Clinical context |
|-------|-----------------|
| `emergency` | Emergency and acute care — prioritises speed and unambiguous terminology |
| `gp` | General practice consultations |
| `specialist` | Specialist consultations — precise, technical terminology |
| `mental_health` | Mental health and psychiatric settings |
| `physical_therapy` | Physiotherapy and rehabilitation |

See [Clinical Domains →](/concepts/clinical-domains/) for how each domain changes translation behaviour.
