All `TolkaClient` methods throw `TolkaApiError` on failure. Never swallow errors silently — in a medical context, a failed translation must result in a clear fallback, not a silent empty string.

---

## `TolkaApiError` shape

```typescript
import { TolkaApiError } from '@tolka/web-sdk';

try {
  const result = await tolka.translate({ ... });
} catch (err) {
  if (err instanceof TolkaApiError) {
    err.errorCode   // string — machine-readable, see Error Catalog
    err.message     // string — human-readable, may change between releases
    err.status      // number — HTTP status, or 0 for network-level failures
    err.suggestion  // string | undefined — human-readable next step
    err.requestId   // string | undefined — include in support tickets
  }
  // Re-throw unknown errors
  throw err;
}
```

:::note[No typed `retryAfter`]
The server sends the `Retry-After` header on `rate_limited` responses, but the current SDK doesn't surface it as a field on `TolkaApiError`. Read the header yourself if you need the exact wait time, or use exponential backoff as shown below.
:::

## Retry pattern

<Tabs>
<TabItem label="TypeScript">
```typescript
import { TolkaClient, TolkaApiError } from '@tolka/web-sdk';

async function translateWithRetry(
  client: TolkaClient,
  params: Parameters<TolkaClient['translate']>[0],
  maxRetries = 3,
) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await client.translate(params);
    } catch (err) {
      if (!(err instanceof TolkaApiError)) throw err;

      const isRetryable = err.status === 429 || err.status === 503;

      if (isRetryable && attempt < maxRetries) {
        const delay = Math.min(1000 * Math.pow(2, attempt) + Math.random() * 500, 30_000);
        await new Promise((r) => setTimeout(r, delay));
      } else {
        throw err;
      }
    }
  }
}
```
</TabItem>
<TabItem label="Python">
```python
import time, random
from tolka import TolkaClient, TolkaApiError

def translate_with_retry(client, params, max_retries=3):
    for attempt in range(max_retries + 1):
        try:
            return client.translate(**params)
        except TolkaApiError as e:
            retryable = e.status in (429, 503)
            if retryable and attempt < max_retries:
                delay = min(2**attempt + random.random(), 30)
                time.sleep(delay)
            else:
                raise
```

## Error handling per code

| `error_code` | Retryable | Recommended action |
|--------------|-----------|--------------------|
| `unauthorized` | No | Check key configuration; alert ops |
| `session_invalid` | No | Create a new session |
| `session_expired` | No | Create a new session; continue encounter |
| `invalid_request` | No | Fix request fields (see `fields` in the response); log and alert |
| `text_too_long` | No | Split text at sentence boundaries |
| `key_not_found` | No | Check the key ID; refresh your key list |
| `org_not_found` | No | Check org configuration; alert ops |
| `rate_limited` | Yes | Read the `Retry-After` header; back off |
| `translation_unavailable` | Yes | Exponential backoff; check status page |
| `provider_unavailable` | Yes | Exponential backoff |
| `provider_rate_limited` | Yes | Exponential backoff |
| `audit_log_unavailable` | Yes | Exponential backoff; alert ops if persistent |
| `storage_error` | Yes | Exponential backoff |
| `internal_error` | Yes | Exponential backoff; report `requestId` if persistent |
| `not_found` | No | Check the request path and method |

## Fallback UI requirements

When all retries are exhausted, your UI **must** show a meaningful fallback:

```typescript
try {
  return await translateWithRetry(tolka, params);
} catch (err) {
  if (err instanceof TolkaApiError) {
    return {
      fallback: true,
      message: 'Translation service is temporarily unavailable. Please use a professional interpreter.',
      requestId: err.requestId,
    };
  }
  throw err;
}
```

Never display an empty translation box to a patient. Always explain what happened and provide an alternative path.
