`TolkaClient` wraps the three translation endpoints — `/translate`, `/safe-translate`, `/session` — with typed methods, automatic retries, and error parsing.

:::note[Admin endpoints aren't wrapped]
`/v1/admin/keys`, `/v1/admin/usage`, `/v1/admin/audit-log`, and `/v1/admin/phrases` have no `TolkaClient` methods — call them directly with `fetch` or cURL. Only `GET /v1/admin/org/branding` has a client method (`getOrgBranding`), covered below. See [Admin Keys](/api-reference/admin-keys/), [Admin — Usage](/api-reference/usage/), and [Admin — Audit Log Export](/api-reference/admin-audit-log/) for the raw HTTP contracts.
:::

## Initialisation

```typescript
import { TolkaClient } from '@tolka/web-sdk';

const tolka = new TolkaClient({
  apiKey: process.env.TOLKA_API_KEY!,
  // Optional overrides — shown values are the SDK's actual defaults:
  baseUrl: 'https://api.tolka.health', // default: "http://localhost:3000" — always set this explicitly outside local dev
  timeout: 15_000,                      // ms, default 15000. Throws TolkaApiError({errorCode: 'network_error'}) on expiry; not retried
  maxRetries: 2,                        // retries on 408/429/500/502/503/504, default 2 (up to 3 attempts total)
  retryBaseDelayMs: 200,                // base delay for the equal-jitter backoff schedule, default 200
});
```

:::caution[Default `baseUrl` is localhost]
The SDK defaults `baseUrl` to `http://localhost:3000` for local development against a self-hosted API. Set it explicitly to `https://api.tolka.health` for anything talking to the real service — nothing will work otherwise.
:::

### Keeping `sk_live_` keys off the client

For browser code, don't pass `apiKey` directly with a live key. Use `getToken` instead — it's called before every request, so your token endpoint controls rotation and expiry, not the SDK:

```typescript
let cached: { token: string; expiresAt: number } | null = null;

const tolka = new TolkaClient({
  baseUrl: 'https://api.tolka.health',
  getToken: async () => {
    if (cached && cached.expiresAt > Date.now() + 30_000) return cached.token;
    cached = await fetch('/api/tolka-token').then((r) => r.json());
    return cached!.token;
  },
});
```

## `tolka.translate(request, opts?)`

`mode: "standard"` always returns a translation, even at low confidence.

```typescript
const result = await tolka.translate({
  text: 'Har du hodepine?',
  source_language: 'no',
  target_language: 'en',
  mode: 'standard',
  context: { domain: 'gp' }, // optional
});

result.translation        // string | null
result.back_translation   // string | null
result.confidence         // number (0–1)
result.risk               // 'low' | 'medium' | 'high' | 'critical' | 'unknown'
result.flags              // { type, detail, severity }[]
result.verified           // boolean
result.metadata           // { latency_ms, model, request_id, data_residency }
```

See [Understanding the Response](/getting-started/understanding-the-response/) for what every field means.

## `tolka.safeTranslate(request, opts?)`

Same request shape as `translate` (`mode` is forced to `"safe"` server-side regardless of what you pass). On a low-confidence or critical-flag result, `translation` is `null` and two extra fields explain why:

```typescript
const result = await tolka.safeTranslate({
  text,
  source_language,
  target_language,
  mode: 'safe',
  context: { domain: 'gp' },
});

if (!result.verified && result.translation === null) {
  console.warn('Withheld:', result.reason_class, result.escalation_options);
}
```

## `tolka.createSession(context, opts?)`

```typescript
const session = await tolka.createSession({
  domain: 'gp',
  speaker: 'doctor', // required
  // intent: 'history_taking', // optional
});

session.session_token  // string — pass this in later translate()/safeTranslate() calls
session.expires_at     // ISO 8601 string
```

Pass the returned `session_token` in subsequent `translate()`/`safeTranslate()` calls (as a top-level `session_token` field on the request) to keep clinical context across a multi-turn conversation. Every response made with a `session_token` includes a refreshed one — store it back, or the 15-minute idle TTL collapses into the 60-minute hard cap.

## `tolka.getOrgBranding(opts?)`

```typescript
const branding = await tolka.getOrgBranding();

branding.display_name  // string | null
branding.logo_url      // string | null
branding.brand_color   // string | null
```

All three fields are nullable — `null` means no override is set. There is no `updateOrgBranding` method yet; `PATCH /v1/admin/org/branding` must be called directly.

## Error handling

All methods throw `TolkaApiError` on failure. See [Error Handling](/sdks/web/error-handling/) for the full field reference and retry patterns.

```typescript
import { TolkaApiError } from '@tolka/web-sdk';

try {
  const result = await tolka.translate({ ... });
} catch (err) {
  if (err instanceof TolkaApiError) {
    console.error(err.errorCode); // e.g. 'rate_limited'
    console.error(err.status);
  }
}
```
