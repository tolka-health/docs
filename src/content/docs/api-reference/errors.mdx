All Tolka API errors follow a consistent, flat envelope:

```json
{
  "error_code": "rate_limited",
  "message": "Rate limit exceeded",
  "suggestion": "Please rephrase using simpler language"
}
```

`suggestion` is only present on the handful of error codes where a human-readable next step applies. Metadata like the request ID and rate-limit counters are delivered as response **headers**, not in the JSON body — see [Headers](/api-reference/headers/):

- `X-Request-Id` — on every response; include this when contacting support.
- `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset` — on every response once rate limiting applies.
- `Retry-After` — seconds to wait, present on `rate_limited` responses.

Always check `error_code` in your code — `message` is for humans and may change between releases.

## Authentication errors (4xx)

### `unauthorized` — 401

The key in the `Authorization` header is malformed, revoked, or does not exist.

**Fix:** Verify the key is an exact copy with no extra whitespace. Confirm it has not been revoked in the dashboard.

---

### `session_expired` — 400

The session token's TTL has elapsed (15 min idle, 60 min hard max).

**Fix:** Create a new session (`POST /v1/medical/session`) and continue the encounter with the new token.

---

### `session_invalid` — 400

The `session_token` field contains a token that is malformed, tampered with, or was issued to a different API key.

**Fix:** Do not modify session tokens. Create a new session if the token is invalid.

---

## Request errors (4xx)

### `invalid_request` — 400

The request body failed schema validation (missing a required field, wrong type, an unsupported `source_language`/`target_language`/`domain` value, or `source_language` equal to `target_language`), or the request otherwise can't be fulfilled as specified (e.g. attempting to revoke the last active API key). The response includes a `fields` value naming the offending field(s) when the failure is a schema violation.

**Fix:** Check the request against the [Interactive Reference](/api-reference/). For supported values, see the [language pairs table](/getting-started/environments/) and the [clinical domains](/concepts/clinical-domains/) list.

---

### `text_too_long` — 400

The `text` field's estimated token count exceeds the input budget for the given source language.

**Fix:** Split the text at sentence boundaries before calling the API. See [POST /translate edge cases](/api-reference/translate/).

---

## Rate limiting (4xx)

### `rate_limited` — 429

You have exceeded your plan's requests-per-minute limit.

**Fix:** Read the `Retry-After` response header (seconds to wait) and the `X-RateLimit-*` headers. Implement exponential backoff. See [Rate Limits](/getting-started/rate-limits/).

---

## Key & org management errors (404)

### `key_not_found` — 404

The API key ID in the URL path does not exist for this org.

---

### `org_not_found` — 404

The organization referenced by the request could not be found.

---

### `not_found` — 404

The route itself does not exist. Check the path and method against the [Interactive Reference](/api-reference/).

---

## Server errors (5xx)

:::note[5xx errors are always retryable]
All 5xx errors are transient. Retry with exponential backoff. If the error persists, check [the support page](/about/support/).
:::

### `translation_unavailable` — 503

The translation pipeline is temporarily unavailable — typically during a deployment or an infrastructure incident.

**Fix:** Implement exponential backoff with jitter starting at 1 second.

---

### `provider_unavailable` — 503

The underlying LLM or embedding provider is unreachable or returned a fatal error.

**Fix:** Retry. If the error persists across multiple requests, check [the support page](/about/support/).

---

### `provider_rate_limited` — 503

The underlying LLM or embedding provider's own rate limit was hit — not yours.

**Fix:** Retry with backoff. This is independent of your own `X-RateLimit-*` headers.

---

### `audit_log_unavailable` — 503

The durable audit-log store is not configured for this environment. Returned only on audit-dependent admin operations.

**Fix:** Contact your Tolka administrator — this is an environment configuration issue, not a client-side bug.

---

### `storage_error` — 500

A storage operation (e.g. API key persistence) failed unexpectedly.

**Fix:** Retry. Log the `X-Request-Id` header for support if it persists.

---

### `internal_error` — 500

An unexpected, uncategorized server error.

**Fix:** Retry. Log the `X-Request-Id` header for support if it persists.

---

## Not an error: safe-mode refusals

`POST /v1/medical/safe-translate` never returns an error code for a low-confidence result. Instead it returns a normal `200` response with `translation: null`, `verified: false`, a `reason_class`, and `escalation_options` describing what to do next (e.g. rephrase, or escalate to a human interpreter). See [POST /safe-translate](/api-reference/translate/) for the full response shape.
