The Admin Keys API lets you programmatically manage API keys for your organisation. These endpoints aren't wrapped by `TolkaClient` — call them with `fetch` or cURL directly.

---

## Endpoints at a glance

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/admin/keys` | List all keys for your org |
| `POST` | `/v1/admin/keys` | Create a new key |
| `POST` | `/v1/admin/keys/:id/rotate` | Create a replacement key, old one stays active |
| `DELETE` | `/v1/admin/keys/:id` | Revoke a key |

There's no `GET /v1/admin/keys/:id` — list all keys and find the one you need by `id` or `key_prefix`/`key_suffix`.

---

## List keys

```bash
curl https://api.tolka.health/v1/admin/keys \
  -H "Authorization: Bearer $TOLKA_API_KEY"
```

Response:
```json
{
  "keys": [
    {
      "id": "key_01HX4K2MN7...",
      "org_id": "org_01HX...",
      "key_prefix": "sk_live_",
      "key_suffix": "a1b2",
      "label": "Production – EHR integration",
      "is_active": true,
      "created_at": "2026-04-01T08:00:00Z",
      "revoked_at": null
    }
  ]
}
```

:::note[Secret is never returned]
The full key secret is only returned once, in the response of `POST /v1/admin/keys` or `POST /v1/admin/keys/:id/rotate`. Every other endpoint returns only `key_prefix` and `key_suffix` — enough to identify a key in your dashboard, never enough to reconstruct it.
:::

:::note[No expiry field]
Keys don't expire on a timer — `is_active`/`revoked_at` are the only lifecycle state. If you need periodic rotation, that's a process you run yourself (see [Key Rotation](/guides/key-rotation/)), not something the API enforces.
:::

## Create a key

```bash
curl -X POST https://api.tolka.health/v1/admin/keys \
  -H "Authorization: Bearer $TOLKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"label": "CI pipeline key"}'
```

Response:
```json
{
  "key": "sk_test_...",
  "id": "key_01HX4K2MN7...",
  "key_prefix": "sk_test_",
  "key_suffix": "c3d4",
  "label": "CI pipeline key"
}
```

`label` is the only accepted field, and it's optional. `key` is the full secret — store it now, it's never shown again.

## Rotate a key (zero-downtime)

Rotation creates a brand-new key and leaves the old one active — there's no automatic expiry window, so you must revoke the old key yourself once you've rolled out the new one.

```bash
curl -X POST https://api.tolka.health/v1/admin/keys/key_01HX.../rotate \
  -H "Authorization: Bearer $TOLKA_API_KEY"
```

Response:
```json
{
  "key": "sk_test_...",
  "id": "key_01HX4K2MN8...",
  "key_prefix": "sk_test_",
  "key_suffix": "e5f6",
  "label": "rotated",
  "old_key_id": "key_01HX4K2MN7...",
  "message": "New key created. Old key remains active until explicitly revoked."
}
```

See the [Key Rotation guide](/guides/key-rotation/) for the full procedure, including the required manual revoke step.

---

## Revoke a key

```bash
curl -X DELETE https://api.tolka.health/v1/admin/keys/key_01HX... \
  -H "Authorization: Bearer $TOLKA_API_KEY"
```

:::caution[Can't revoke your last active key]
Returns `400 invalid_request` if this would leave your org with zero active keys. Create a replacement first.
:::
